Голос, который остаётся с ребёнком

Науз записывает сказки, книги и письма голосами родителей — один раз, чтобы включать их сколько угодно вечеров, даже когда мама или папа не могут быть рядом. Название — от древнего оберега: узла на нити, который хранит связь между человеком и тем, что ему дорого.

Отсюда и весь тон интерфейса: тёплый, тихий, без развлекательности. Ничего мультяшного — это не игрушка, а способ сохранить голос близкого человека для ребёнка.

НАУЗ
Трансформация экранов

От функционального UI к дизайн-системе Науза

Сегодня приложение работает на Next.js + Tailwind как обычный функциональный интерфейс: формы, списки, стандартные компоненты ElevenLabs UI. Дизайн-система Науза не меняет структуру данных или логику — она меняет то, как эти экраны выглядят и ощущаются.

Согласие и KYC

Сейчас согласие — чекбокс в форме /voices/new, а запуск KYC через Didit выглядит как переход на сторонний сервис без визуальной подготовки. В новой версии это два экрана на весь размер, с крупным serif-заголовком, объясняющим, зачем нужен каждый шаг — согласие и подтверждение личности становятся одним бережным ритуалом, а не формальностью перед формой.

Запись голоса

Компонент VoiceRecorder и визуализация LiveWaveform сегодня — техническая индикация уровня сигнала. В новой версии волна становится главным элементом экрана, крупная и цвета глины, а фраза для чтения набрана как строка из книги, а не техническая инструкция.

Кабинет владельца

Разделы «Голоса», «Тексты» и «Книги» сегодня — отдельные списки и таблицы, статусы — текстовые бейджи. В новой версии это один кабинет с мягкими вкладками; статусы голоса (awaiting_kyc → ready → revoked) становятся цветными пилюлями, а карточки голосов и текстов получают равный визуальный вес — это книжная полка, а не админ-панель.

Письмо, сказка и библиотека шаблонов

Сегодня это обычная textarea и список story_templates. В новой версии поле ввода оформлено как страница письма — serif, увеличенный интерлиньяж; библиотека шаблонов — сетка карточек с тематическими метками вместо сухого перечня.

Книга: главы, голоса, вопросы на понимание

Выбор голоса на главу сегодня — обычный select, recap — чекбокс без объяснения. В новой версии список глав похож на содержание книги; выбор чтеца — это аватар голоса, а не выпадающий список; переключатель вопросов на понимание сопровождается понятной подписью и видимой настройкой паузы (recapDelaySeconds), а не скрыт в опциях.

Публичная ссылка для слушателя

Сегодня /s/[token] и /b/[token] используют стандартный плеер ElevenLabs UI (Progress/Time/Duration/Speed) на белом фоне. В новой версии это тёмный тёплый экран для ребёнка: имя того, кто читает, название истории и одна крупная кнопка воспроизведения — никаких настроек скорости или элементов, ненужных слушателю без аккаунта.

Telegram-бот

Бот остаётся текстовым каналом (/voices, /newvoice, /books) и не входит в этот визуальный проход — его тон и структура команд можно привести в соответствие отдельно, после того как утвердится дизайн-система веба.

Implementation guide

Как внедрять

Ориентир для команды: три экрана выше (запись голоса, кабинет, экран слушателя) проработаны детально и могут внедряться первыми. Остальные три — направление, которое нужно доработать в том же духе перед вёрсткой.

1. Токены дизайн-системы

Добавить в Tailwind-конфиг как тему, а не хардкодить оттенки по месту:

colors: { paper: 'oklch(0.97 0.012 60)', surface: 'oklch(0.94 0.014 58)', ink: 'oklch(0.24 0.02 50)', 'ink-soft': 'oklch(0.45 0.02 50)', clay: 'oklch(0.62 0.09 45)', sage: 'oklch(0.62 0.09 145)', border: 'oklch(0.87 0.02 55)', } fontFamily: { serif: ['Piazzolla', 'serif'], // сказки, письма, заголовки sans: ['Manrope', 'sans-serif'] // интерфейс }

2. Порядок внедрения

Начинать с экрана слушателя (/s/[token]) — он не требует авторизации, у него нет побочных состояний и он даёт самую заметную отдачу для меньшего объёма работы. Дальше — кабинет владельца (общий каркас: сайдбар + вкладки переиспользуются на всех авторизованных страницах), затем запись голоса, письмо/сказка, книга. Telegram-бот и админка куратора — вне этого прохода.

3. Соответствие компонентов

Экран слушателя
AudioPlayerProvider/Progress/Time из ElevenLabs UI — оставить логику, полностью переопределить стили (тёмный фон, один крупный контрол, без Speed и второстепенных кнопок).
Кабинет
Новый layout-компонент с сайдбаром оборачивает существующие страницы /voices, /stories, /books — данные и запросы не меняются, меняется только разметка списков и карточек.
Запись голоса
VoiceRecorder и LiveWaveform — переопределить только цвета и размер волны; логика записи, загрузка образцов по одному файлу за запрос — без изменений.
Книга
Конечный автомат стадий "recap" | "waiting" | "chapter" в ChapterPlayer остаётся как есть — новый UI просто подписывается на его состояние для анимации перехода между recap и главой.

4. Состояния, которые нужно предусмотреть

Пустой кабинет без единого голоса (первый вход); голос в статусе failed — отдельная пилюля и подсказка «попробовать снова»; генерация аудио в процессе (несколько параллельных генераций одной главы разными голосами — раздел 5.5 функционального описания); отозванный голос с недоступными для повторной генерации, но проигрываемыми старыми записями; истёкшая/перевыпущенная публичная ссылка.

5. Что не входит в этот проход

Telegram-бот (текстовый канал, отдельная задача); экраны оператора/куратора (миграции, без UI); мелкая моторика форм — точные размеры хитзон, фокус-стейты, обработка ошибок валидации — на этапе вёрстки.
