# Науз — полное описание приложения (MECE)

Этот документ — исчерпывающая инвентаризация того, что приложение сейчас
делает: цели, пользователи, возможности и ограничения. Структура —
MECE (Mutually Exclusive, Collectively Exhaustive): каждый раздел не
пересекается с другими и вместе они покрывают весь функционал.
Для истории замысла и мотивации см. [overview.md](overview.md).

Дата среза: 2026-08-04, по состоянию кода в этой ветке.

---

## 1. Цели продукта

1.1. **Сохранить голос родителя/родственника** — снять голосовой слепок один
     раз и переиспользовать его сколько угодно раз, сколько угодно долго.

1.2. **Дать ребёнку слышать этот голос**, когда владелец голоса физически
     не может прочитать текст сам — в разъезде, недоступен, тяжело болен,
     умер, — читая сказки, письма и главы книг.

1.3. **Не допустить злоупотребления клонированием голоса** — использовать
     голос может только тот, кто подтвердил личность и дал согласие;
     каждый выпущенный файл прослеживаем до владельца голоса.

Цели 1.1–1.3 взаимоисключающи: сохранение слепка, доставка ребёнку и защита
от злоупотреблений — три разных инженерных задачи, реализованные разными
подсистемами (см. разделы 3–5).

---

## 2. Роли пользователей

2.1. **Владелец голоса** — взрослый, который проходит KYC и записывает
     свой голос. Управляет своими голосами, текстами и генерациями через
     веб (после magic-link входа) или Telegram-бота (после привязки
     аккаунта).

2.2. **Слушатель (ребёнок или получатель письма)** — не имеет и не должна
     требоваться учётная запись. Получает доступ только через публичную
     ссылку (раздел 6) — без логина, без регистрации.

2.3. **Оператор/разработчик** — обслуживает инфраструктуру (Supabase,
     ElevenLabs, Didit, Telegram), не имеет отдельного UI в приложении,
     работает через миграции и переменные окружения.

Роли взаимоисключающи по правам доступа: у 2.1 есть аккаунт и RLS-scoped
доступ к своим данным, у 2.2 — только чтение через service-role по
непредсказуемому токену, у 2.3 — прямой доступ к инфраструктуре в обход
приложения.

---

## 3. Управление голосом (voice lifecycle)

3.1. **Создание голосового профиля** — `/voices/new`: ввод названия
     ("Мама", "Дедушка Игорь"), явное согласие на использование голоса.

3.2. **Подтверждение личности (KYC)** — через провайдера Didit
     ([src/lib/kyc/didit.ts](../src/lib/kyc/didit.ts)): запуск верификации,
     приём результата вебхуком с проверкой HMAC-SHA256 подписи
     ([src/app/api/kyc/webhook/route.ts](../src/app/api/kyc/webhook/route.ts)).
     Голос нельзя клонировать до статуса `approved`.

3.3. **Запись образца голоса** — `VoiceRecorder`
     ([src/app/voices/[id]/voice-recorder.tsx](../src/app/voices/%5Bid%5D/voice-recorder.tsx)):
     запись через `MediaRecorder`, live-визуализация уровня сигнала
     (`LiveWaveform`, тот же компонент ElevenLabs UI, что и в плеере
     готовых записей), загрузка нескольких образцов по одному файлу за
     запрос (обход лимита тела запроса ~4.5MB на serverless-функцию).

3.4. **Клонирование голоса** — после сбора образцов вызывается ElevenLabs
     IVC (Instant Voice Cloning), результат — `elevenlabs_voice_id`,
     статус голоса переходит в `ready`.

3.5. **Переименование голоса** — смена `label` в любой момент, пока голос
     не отозван (`RenameVoiceButton`, `PATCH /api/voices/[id]`, ограничен
     только полем `label`).

3.6. **Отзыв/удаление голоса** — `DELETE /api/voices/[id]`: если у голоса
     нет ни одной готовой генерации — удаляется полностью (каскадом с
     KYC-записями); если генерации есть — голос помечается `revoked`
     (клон в ElevenLabs и сырые образцы удаляются, но уже сгенерированные
     аудиозаписи и их подпись остаются доступны).

Жизненный цикл голоса — конечный автомат со статусами `awaiting_kyc →
kyc_approved → cloning → ready → (revoked | failed)`; разделы 3.1–3.6
взаимоисключающи как последовательные стадии одного объекта.

## 4. Тексты для озвучки

Приложение различает два независимых источника текста — по правам
редактирования и по структуре:

4.1. **Разовые сказки и письма** (`stories`) — один законченный текст,
     принадлежит владельцу голоса. Два способа получить текст:
     - 4.1.1. Написать свой текст с нуля (`/stories/new`, режим "письмо").
     - 4.1.2. Выбрать готовый шаблон из библиотеки сказок
       (`story_templates`) — куратор поддерживает `text_plain` (для показа
       пользователю) и `text_marked` (с ElevenLabs-разметкой: интонационные
       теги вроде `[задумчиво]`, ударения апострофом после гласной,
       например "Лиса'") — в TTS уходит именно `text_marked`.

4.2. **Многоглавные книги** (`books` → `book_chapters`) — куратор
     публикует книгу целиком главами заранее; пользователь не создаёт и
     не редактирует текст книги, а только выбирает, каким голосом озвучить
     каждую главу. Перед главой №2 и далее может идти отдельно озвученный
     блок вопросов на понимание предыдущей главы (`recap_questions_marked`,
     опционально — только если куратор его подготовил).

Разделение 4.1/4.2 взаимоисключающе: `stories` не имеют глав и вопросов на
понимание, `book_chapters` не редактируются пользователем и не имеют
собственной публичной страницы вне книги.

## 5. Генерация аудио

5.1. **Синтез речи** — ElevenLabs `eleven_v3`
     ([src/lib/elevenlabs/client.ts](../src/lib/elevenlabs/client.ts)),
     голосом конкретного `voice_id` пользователя.

5.2. **Длинные тексты** — тексты длиннее лимита ElevenLabs на один запрос
     (5000 символов) режутся по границам предложений
     ([src/lib/elevenlabs/chunk-text.ts](../src/lib/elevenlabs/chunk-text.ts))
     и склеиваются через `previous_text`/`next_text`/`previous_request_ids`
     для сохранения интонационной связности между кусками
     ([src/lib/elevenlabs/long-speech.ts](../src/lib/elevenlabs/long-speech.ts)).
     Общая логика используется и сказками, и главами книг.

5.3. **Регулировка скорости чтения** — выбор из набора допустимых
     значений скорости при генерации ([src/lib/stories/speed-options.ts](../src/lib/stories/speed-options.ts)).

5.4. **Цифровой водяной знак** — каждая генерация получает `watermark_id`
     ([src/lib/watermark/index.ts](../src/lib/watermark/index.ts)),
     привязанный к владельцу/голосу/генерации; текущая реализация — метаданные
     и ID3-теги ([src/lib/provenance/id3-tags.ts](../src/lib/provenance/id3-tags.ts)),
     единая точка интеграции, куда позже подключается настоящая
     аудио-схема встраивания сигнала (задокументировано как TODO в коде).

5.5. **Несколько версий одной генерации разными голосами** — сказка или
     глава книги не привязаны жёстко к одному голосу: одна и та же глава
     может быть параллельно и независимо озвучена несколькими голосами
     владельца ("кто прочитает?" на уровне главы), генерации идут
     конкурентно и отслеживаются независимо (`Set` активных задач в UI, а
     не единственное значение).

5.6. **Хранение результата** — готовые файлы лежат в приватном
     Supabase Storage, отдаются только по подписанным URL (signed URL),
     не публичны напрямую.

## 6. Прослушивание и раздача

6.1. **Прослушивание в приложении** (для владельца) — `/stories/[id]` и
     `/books/[id]`, требует входа; плеер собран на компонентах ElevenLabs UI
     (`AudioPlayerProvider`/`Button`/`Progress`/`Time`/`Duration`/`Speed`).

6.2. **Публичная ссылка на сказку/письмо** — `/s/[token]`: не требует
     входа, `share_token` — 16 случайных байт, разрешается через
     service-role-клиент в обход RLS. Токен можно перевыпустить (кнопка
     "обновить ссылку"), что аннулирует старую ссылку.

6.3. **Публичная ссылка на книгу** — `/b/[token]`: аналогично, но
     сущность `book_share_links` осознанно скоуплена на пару
     `(book_id, owner_id)`, а не на `book_id` и не на `voice_id` — потому
     что одну и ту же куратором опубликованную книгу разные пользователи
     озвучивают своими голосами, а один владелец может озвучить разные
     главы разными своими голосами. Ссылка показывает по каждой главе
     все существующие версии озвучки этого владельца, слушатель выбирает
     голос сам.

6.4. **Раздача через Telegram-бота** — привязка Telegram-аккаунта к
     аккаунту приложения (`telegram_links`), команды бота
     ([src/lib/telegram/bot.ts](../src/lib/telegram/bot.ts)):
     - `/voices` — список голосов, создание нового.
     - `/newvoice` — начать новый голосовой профиль.
     - `/books` — выбор книги → выбор голоса-чтеца → выбор главы;
       если у главы есть вопросы на понимание — сначала отдельным
       аудио-сообщением приходит recap, затем аудио главы.
     - Пошаговые сценарии ожидания ввода (email/OTP/имя голоса) хранятся
       как состояние в `telegram_links`, а не в памяти процесса.

Разделы 6.1–6.4 взаимоисключающи по каналу доступа (веб-с-авторизацией /
веб-без-авторизации-сказка / веб-без-авторизации-книга / Telegram) и
вместе покрывают все существующие способы прослушать готовое аудио.

## 7. Управление воспроизведением книги (поверх раздела 6)

Специфично для книг (не применимо к разовым сказкам/письмам, у которых
нет глав и recap):

7.1. **Вопросы на понимание** — можно включить или выключить целиком
     (`includeRecap`).

7.2. **Пауза между recap и главой** — настраиваемая задержка в секундах
     (`recapDelaySeconds`) перед стартом самой главы после вопросов.

7.3. **Пауза воспроизведения** — реальная пауза (не просто остановка
     таймера) на любой стадии, реализована конечным автоматом стадий
     `"recap" | "waiting" | "chapter"` в `ChapterPlayer`.

---

## 8. Идентификация и доступ

8.1. **Вход без пароля** — magic link на email через Supabase Auth,
     обновление сессии в `middleware.ts` на каждом запросе.

8.2. **Защищённые разделы** — `/dashboard`, `/voices`, `/stories`,
     `/books` требуют входа, редиректят на `/login?redirectTo=...`.
     `/s/[token]` и `/b/[token]` сознательно исключены — они публичные
     по замыслу.

8.3. **Многопользовательская изоляция данных** — `voices`, `stories`,
     `book_chapter_generations` принадлежат конкретному владельцу
     (`owner_id`) и защищены RLS; `books`/`book_chapters`/
     `story_templates` — общий, курируемый контент без владельца, доступный
     на чтение всем авторизованным пользователям.

---

## 9. Явные ограничения (из чего складывается ME — что приложение НЕ делает)

Перечислены, чтобы описание было исчерпывающим и в отрицательную сторону:

- Слушатель не может ничего создавать, редактировать или комментировать —
  только слушать по ссылке.
- Владелец голоса не редактирует текст книг — только сказки/письма
  собственного сочинения или выбранные из шаблонов.
- Нет самостоятельной публикации новых книг/шаблонов пользователями —
  это курируемый контент, добавляется через миграции.
- Нет пересинтеза чужого голоса — голос доступен только своему владельцу
  (или тому, кому он явно передан по ссылке `/b/[token]`, которая не
  раскрывает исходный образец, только готовые аудиофайлы).
- Watermarking — сейчас только метаданные/ID3, не устойчивая к сжатию
  аудио-сигнатура (зафиксировано как открытый TODO, не скрытая недоделка).

## 10. Технологический стек (для полноты, не для целеполагания)

Next.js 16 (App Router) + React 19 + TypeScript, Tailwind CSS v4,
Supabase (Postgres + Auth + Storage + RLS), ElevenLabs API (TTS +
Instant Voice Cloning), Didit (KYC), Telegram Bot API. Подробности
компонентов озвучки/визуализации — в плане `ElevenLabs UI + Tailwind-
примитивы` (актуален на момент написания, часть уже реализована:
`AudioPlayer*`, `LiveWaveform`).
